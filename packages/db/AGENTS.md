# packages/db

Drizzle ORM on Turso (libSQL): the schema, its migrations, a client factory and a demo
seed. The schema file documents each table. See the root `AGENTS.md` for repo-wide rules.

```sh
pnpm db:dev                         # local libSQL on :8080 (.data/local.db)
pnpm db:generate                    # write a migration after editing src/schema
TURSO_DATABASE_URL=http://127.0.0.1:8080 pnpm db:migrate   # apply it locally
pnpm db:studio                      # browse the local DB
TURSO_DATABASE_URL=http://127.0.0.1:8090 pnpm --filter @workspace/db demo
                                    # 3 months of sample data, local URLs only
```

`pnpm db:migrate` without `TURSO_DATABASE_URL` targets `http://127.0.0.1:8080`, and it
doesn't read `.env.local`. Always pass the URL explicitly.

## Layout

- `src/schema/app.ts`: every table. Money is integer cents, `local_date` is the owner's
  calendar day, and soft delete is `deleted_at`.
- `migrations/`: generated by drizzle-kit, with `meta/` snapshots and `_journal.json`.
- `src/index.ts`: `createDb({ url, authToken })` (accepts `libsql://`, `http://` and
  `file:` URLs) and `seedDefaults`.
- `scripts/demo.ts`: the demo seed. Its split bills have no `entry_id`, so split features
  don't show on demo data.

## Schema changes

1. Edit `src/schema/app.ts`, then `pnpm db:generate`. Never hand-edit generated
   migrations or snapshots.
2. **Keep migrations additive** (new tables, nullable or defaulted columns). On `main`, CI
   applies migrations after its checks, while Vercel deploys the same push on its own, so
   for a minute or two both the old and the new code can run against either schema.
3. Apply the migration to the local dev DB on `:8080` with the URL passed explicitly, and
   run `pnpm test`: the `apps/goatside` tests apply every migration to a fresh database.
4. Never run migrations against a remote Turso database unless asked. Production gets
   them from CI (`migrate` job) or the owner's own `pnpm db:migrate`.
5. Update any docs that describe the tables (`apps/web/content/docs`).
