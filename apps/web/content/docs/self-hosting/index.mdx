---
title: Deploy to Vercel
description: Put your own Goatside on Vercel with a Turso database, step by step.
---

A Goatside deploy is one Vercel project, built from `apps/app`, and one Turso database.
You'll need a [GitHub](https://github.com), [Vercel](https://vercel.com) and
[Turso](https://turso.tech) account, Node 22.12 or newer and
[pnpm](https://pnpm.io) on your computer, and the
[Turso CLI](https://docs.turso.tech/cli).

<Steps>
<Step>

### Fork the repo

[Fork goatside on GitHub](https://github.com/joshxfi/goatside/fork), then clone your fork
and install its dependencies:

```sh
git clone https://github.com/<you>/goatside
cd goatside
pnpm install
```

Your fork is what Vercel deploys. Keeping it synced with this repo is how you
[get updates](/docs/self-hosting/updating).

</Step>
<Step>

### Create the database

Create a Turso database and a token for it:

```sh
turso auth login
turso db create goatside
turso db show goatside --url          # libsql://goatside-<you>.turso.io
turso db tokens create goatside
```

Keep the URL and the token. They're your `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN`.

</Step>
<Step>

### Set up the tables

From your clone, apply the migrations to the new database:

```sh
TURSO_DATABASE_URL=libsql://goatside-<you>.turso.io \
TURSO_AUTH_TOKEN=<token> \
pnpm db:migrate
```

To have later migrations applied for you, add `TURSO_DATABASE_URL` and
`TURSO_AUTH_TOKEN` as Actions secrets on your fork, under **Settings → Secrets and
variables → Actions**. Every push to `main` then applies new migrations once the
checks pass. More in [Database](/docs/self-hosting/database#migrations).

<Callout type="warn">
  Vercel doesn't migrate the database. Without the secrets, run this again
  whenever an update adds a migration.
</Callout>

</Step>
<Step>

### Import it in Vercel

In Vercel, choose **Add New → Project** and import your fork. Set **Root Directory** to
`apps/app`. Vercel detects TanStack Start and builds it with Nitro. Leave the other build
settings as they are.

</Step>
<Step>

### Add your environment variables

Before you deploy, add these under **Environment Variables**:

| Variable             | Value                                                              |
| -------------------- | ------------------------------------------------------------------ |
| `GOATSIDE_USERNAME`  | The username you'll sign in with                                   |
| `GOATSIDE_PASSWORD`  | A password of 12 or more characters. The app lives on a public URL |
| `SESSION_SECRET`     | 32 or more random characters. Run `openssl rand -base64 32`        |
| `TURSO_DATABASE_URL` | Your database URL from step 2                                      |
| `TURSO_AUTH_TOKEN`   | Your token from step 2                                             |

You don't need `AI_GATEWAY_API_KEY` on Vercel. See
[Environment variables](/docs/self-hosting/environment) for everything Goatside reads.

</Step>
<Step>

### Turn on AI Gateway

The agent runs on [Vercel AI Gateway](https://vercel.com/docs/ai-gateway). On Vercel it
signs in with your project's OIDC token, so there's no key to manage. Open **AI Gateway**
on your Vercel team's dashboard and enable it.

Skip this and Goatside still works, without the agent. See
[Running without AI](/docs/guide/privacy#running-without-ai).

</Step>
<Step>

### Deploy and sign in

Deploy, open your project's URL and sign in with your username and password. Goatside
adds the default categories the first time you sign in.

Then [install it on your phone](/docs/guide/phone) and log your first entry.

</Step>
</Steps>

## Pick a function region

This step is optional. Each request makes a few database calls, so the app is fastest
when its function runs near your database. In your Vercel project, open **Settings →
Functions** and set the **Function Region** to the one closest to your Turso location.
For Singapore, that's `sin1`.
